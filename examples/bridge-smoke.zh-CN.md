# 一次真实的 Bridge 双对话任务

[仓库首页](../README.zh-CN.md#example) · [English](bridge-smoke.md)

2026 年 11 月 1 日，新用户安装验收使用隔离项目，在两个已有 Codex 对话中
运行了已安装的 Byte 包。辅助对话的原生配置选择 gpt-6-luna。任务是一个小型
CSV 工具，没有调用研究训练或创建定时任务。

1. **安装：** skills CLI 1.7.4 发现并复制恰好 14 个 Byte 入口；显式 bootstrap
   核验了 202 个 Bridge 运行文件并安装依赖。安装后的七步工作流模板也通过校验并保存到本地。
2. **派发：** 主会话固定任务、允许路径、验收标准和返回路线，Bridge 通过
   Codex 原生队列送达已登记的辅助对话。
3. **执行与回传：** 辅助对话用 Python 标准库实现 CSV 分组命令，运行四项
   单元测试，通过 Bridge 回报四个有哈希的实际产物。
4. **独立验收：** 主会话用自己的 Decimal 计算核验主数据，再生成事先未公开
   的测试输入，黑盒运行辅助对话的 CLI，并重跑测试。受保护的验收脚本未被修改。
5. **继续执行：** 主会话实际运行预先固定的下一步，记录已核验的验收结果。
   Bridge 将两个动作与真实完成的原生命令记录匹配，最终达到
   `task=verified`、`return=main_continued`、`continuation_verified=true`。
6. **清理：** 停止此次拥有的测试服务，没有遗留的新定时任务或新会话持续空查。

真实测试先发现了失败：裸通知导致回答旧话题；错误的只读命令使另一次尝试停住；
过长的主对话历史又使动作证明查询失败。失败任务保留记录并明确取消；随后修正
接收指引和逐轮历史读取。普通文字回复现在只算接收，不代表完成工作。

修复后的快照通过 219 项 Node、122 项 Byte Python 和 9 项 Bridge Python 测试。
本次真实运行验证的是这两个已识别的 Codex 对话，不代表所有客户端、未加载对话的
即时唤醒或长训练都已在本次验证。

复用时，可以让 `$byte-bridge` 连接选定的已有对话，再派发明确文件范围、验收标准
和返回路线的小任务；先核实登记身份、权限和原生客户端兼容性。自然语言自动选择
能力用 `$byte-do`，默认完整流程用 `$byte-auto`，保存自定义流程用 `$byte-workflow`。
